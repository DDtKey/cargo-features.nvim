*cargo-features.nvim.txt* Native Cargo feature UI for rust-analyzer

==============================================================================
INTRODUCTION                                      *cargo-features.nvim*

cargo-features.nvim provides a dependency-free floating window for toggling
Cargo features and applying them to active rust-analyzer LSP clients.

Requirements:
- Neovim 0.11+
- An already-running rust-analyzer client
- Optional cargo executable for best feature discovery

Client detection:
  The plugin recognizes the canonical `rust-analyzer` client name, the
  `rust_analyzer` compatibility alias, and custom-named clients launched with
  the `rust-analyzer` executable.

==============================================================================
COMMANDS                                      *cargo-features-commands*

:CargoFeatures
    Open the Cargo feature manager for the nearest Cargo.toml.

:CargoFeaturesDebug
    Print active rust-analyzer clients, attachment state, roots, workspace
    folders, and whether each client covers the current Cargo manifest.

:CargoFeaturesApplyProfile [name]
    Apply a saved Cargo feature profile to matching rust-analyzer clients.
    With a name, apply that saved profile. When both package and workspace
    profiles have the same name, the package profile wins because it is the
    more local context. Without a name, open a vim.ui.select picker for saved
    package and workspace profiles in the current Cargo context.

:CargoFeaturesReset
    Reset plugin-applied Cargo feature overrides for the nearest Cargo.toml.
    Use :CargoFeaturesReset! to force clearing matching live Cargo feature
    settings when no plugin-owned override is remembered.

==============================================================================
LUA API                                          *cargo-features-api*

require("cargo-features").setup({opts})          *cargo-features.setup()*
    Configure the plugin.

require("cargo-features").open()                 *cargo-features.open()*
    Open the floating UI.

require("cargo-features").apply({features}, {opts})   *cargo-features.apply()*
    Apply a list of feature names to matching rust-analyzer clients. Pass a
    bufnr or manifest_path in opts to avoid global ambiguity.

    opts:
      bufnr                       Buffer used to find attached clients.
      manifest_path               Cargo.toml path used to scope clients.
      has_default                 Whether default feature state is managed.
      default_enabled             Desired default feature state.
      scope                       "package" or "workspace".
      remember                    Store the selection for in-session reapply.
                                  UI apply passes this explicitly.
      allow_global                Apply to all rust-analyzer clients only when
                                  explicitly true.

require("cargo-features").reset({opts})          *cargo-features.reset()*
    Reset plugin-applied Cargo feature overrides for matching rust-analyzer
    clients. This removes the live override instead of applying an empty
    feature list. The current buffer and nearest Cargo.toml are used when opts
    does not provide a bufnr or manifest_path.

    opts:
      bufnr                       Buffer used to find attached clients.
      manifest_path               Cargo.toml path used to scope clients.
      workspace_root              Cargo workspace root, when known.
      scope                       "package" or "workspace".
      force                       Clear matching live Cargo feature settings
                                  even when no plugin-owned override is
                                  remembered.

require("cargo-features").apply_profile({name}, {opts}) *cargo-features.apply_profile()*
    Load a named profile and apply it to matching rust-analyzer clients. The
    current buffer and nearest Cargo.toml are used when opts does not provide
    a bufnr or manifest_path. If name is omitted, persistence.default_profile
    is used.

require("cargo-features").save_profile({name}, {opts})   *cargo-features.save_profile()*
    Experimental pre-1.0 helper. Save a named profile. opts.manifest_path is
    required. opts.features, default_enabled, scope, workspace_root, and
    package_name are stored when provided.

require("cargo-features").load_profile({name}, {opts})   *cargo-features.load_profile()*
    Experimental pre-1.0 helper. Load a named profile for a manifest/workspace
    key.

require("cargo-features").delete_profile({name}, {opts}) *cargo-features.delete_profile()*
    Experimental pre-1.0 helper. Delete a named profile for a
    manifest/workspace key.

require("cargo-features").list_profiles({opts})          *cargo-features.list_profiles()*
    Experimental pre-1.0 helper. Return sorted profile names for a
    manifest/workspace key.

    Profile keys:
      Package profiles use opts.manifest_path.
      Workspace profiles use opts.workspace_root when scope = "workspace".
      save_profile() still requires opts.manifest_path so the stored profile
      contains the Cargo.toml it came from.

DEFAULT CONFIG                                *cargo-features-config*
>
require("cargo-features").setup({
  cargo = {
    use_metadata = true,
    metadata_timeout = 3000,
    metadata_extra_args = {},
    metadata_env = {},
    metadata_cwd = nil,
  },
  lsp = {
    reapply = true,
  },
  persistence = {
    default_profile = "default",
    save_on_apply = false,
    load_on_open = "never",
    apply_on_attach = false,
  },
  ui = {
    ascii_icons = false,
    border = "rounded",
    height = 18,
    title = "Cargo Features",
    width = 60,
    icons = {
      checked = "☑",
      unchecked = "☐",
      ascii_checked = "[x]",
      ascii_unchecked = "[ ]",
    },
    keymaps = {
      toggle = { "<CR>", " " },
      toggle_all = "A",
      apply = "W",
      reset = "R",
      save_profile = "S",
      close = { "q", "<Esc>" },
    },
  },
})
<

Cargo options:
  use_metadata
      Prefer async `cargo metadata --no-deps` for feature discovery.

  metadata_timeout
      Timeout in milliseconds before falling back to simple TOML parsing.

  metadata_extra_args, metadata_env, metadata_cwd
      Escape hatches for projects that need non-default Cargo invocation.

LSP options:
  reapply
      true by default. Enables session-local LspAttach reapply. UI-applied
      selections are remembered in memory and reapplied to matching
      rust-analyzer clients that attach later in the same Neovim session, but
      only when the new client has no explicit Cargo/check feature settings.
      Set false to disable automatic session reapply.

Persistence options:
  Profile storage is available for explicit save/load actions under
  stdpath("state")/cargo-features.nvim/profiles.json. Profiles are user-local
  global storage keyed by absolute workspace/manifest paths, not project-local
  files.

  default_profile
      Profile name used for automatic save/load and as the default value in the
      UI save prompt.

  save_on_apply
      Save the UI-applied selection to default_profile after successful UI
      apply.

  load_on_open
      "never" by default. Controls profile preselection on UI open:
        "never"        Never preselect from profiles.
        "if_no_client" Load the default profile only when no matching
                       rust-analyzer client is available.
        "always"       Load the default profile even when rust-analyzer has
                       current feature state.

  apply_on_attach
      false by default. When true, apply default_profile to matching
      rust-analyzer clients when they attach, but only when the client has no
      explicit Cargo/check feature settings.

Runtime behavior:
  Applying features mutates live rust-analyzer settings and sends
  workspace/didChangeConfiguration. UI apply also stores the selection in
  memory and reapplies it when a matching rust-analyzer client attaches later
  in the same Neovim session. Lua callers should pass remember = true when they
  want this behavior.

  Default features are controlled separately from named feature checkboxes.
  When shown, the Default features row controls cargo.noDefaultFeatures. Named
  feature rows are explicit cargo.features selections only. A (default) suffix
  means the feature is directly listed in [features].default. In standalone
  package roots, those rows are effectively enabled and frozen while Default
  features is enabled; uncheck Default features first if you want to disable or
  explicitly control them. In workspace/member views, the marker is
  informational and the rows remain toggleable explicit selections.

  Unchecking every feature applies an explicit empty feature set. Reset is
  different: it removes the plugin-applied override and lets rust-analyzer use
  Cargo.toml/default Cargo behavior again.

  :CargoFeaturesReset clears plugin-applied live overrides remembered in the
  current Neovim session and does not delete disk profiles.
  :CargoFeaturesReset! can clear matching live Cargo feature settings without
  an ownership record. Reset restores check settings the plugin changed.
  Reset does not delete disk profiles.

  :CargoFeaturesApplyProfile applies a saved profile directly to rust-analyzer.
  With an argument, it applies that profile directly, preferring a package
  profile over a workspace profile when both have the same name. Without an
  argument, it opens a built-in vim.ui.select picker for package and workspace
  profiles saved in the current Cargo context. load_on_open = "never" only
  disables automatic UI preselection; profiles can still be applied explicitly
  with :CargoFeaturesApplyProfile or require("cargo-features").apply_profile().

  In the UI, S saves the current checkbox selection as a named profile without
  applying it to rust-analyzer or closing the UI. Pressing Enter at the prompt
  saves to persistence.default_profile, normally "default". W applies to
  rust-analyzer; when persistence.save_on_apply = true, it also saves
  default_profile after a successful apply. Automatic save/load/apply only uses
  default_profile; S and :CargoFeaturesApplyProfile handle named profiles
  explicitly.

  load_on_open is UI preselection only. It does not apply a profile to
  rust-analyzer on startup. Use persistence.apply_on_attach = true to apply
  default_profile to matching rust-analyzer clients when they attach. This
  attach-time apply skips clients with explicit Cargo/check feature settings.

  Live rust-analyzer settings are the source of truth while a client is
  attached. Session-local reapply only runs when the new client has no explicit
  Cargo/check feature settings, so it does not overwrite user-authored
  rust-analyzer config.

  Reapply groups remembered selections by Cargo workspace. If one
  rust-analyzer client appears to cover multiple unrelated Cargo workspaces,
  automatic reapply is skipped instead of sending a mixed cargo.features list.

  Buffer-attached rust-analyzer clients are trusted first. Root/workspace
  matching is used to choose between clients when possible, and as the fallback
  when no rust-analyzer client is attached to the current buffer.

  cargo.noDefaultFeatures is workspace-global. In workspace contexts, the
  Default features row controls that workspace-global setting. Member views
  display local feature names when possible, but apply package-qualified
  feature names when rust-analyzer needs them. If remembered default states ever
  conflict inside one workspace, reapply keeps defaults enabled when any
  remembered entry enables them.

  After apply/reset, the plugin makes a private best-effort reattach of loaded
  Rust buffers attached to the updated rust-analyzer clients to refresh
  inactive-code highlighting. It does not reload files, delete buffers, open
  unloaded buffers, or restart rust-analyzer. Some setups may still require
  closing and reopening the affected buffer. This does not mean the feature
  config failed to apply.

  Disk persistence uses a versioned named-profile file:
>
  {
    "version": 1,
    "profiles": {
      "/abs/workspace-or-manifest-key": {
        "default": {
          "features": ["serde"],
          "default_enabled": true,
          "scope": "package",
          "manifest_path": "/abs/path/Cargo.toml",
          "workspace_root": "/abs/workspace",
          "package_name": "my-crate"
        }
      }
    }
  }
<

  Live apply can be checked locally with `just validate-ra`, which prints the
  rust-analyzer version it used.

  Persistence is split into separate behaviors:
    save_on_apply  Save the UI-applied selection to default_profile.
    load_on_open   Control whether opening the UI preselects default_profile.
    apply_on_attach
                  Apply default_profile to matching rust-analyzer clients on
                  attach when they have no explicit Cargo/check feature config.

  Profile storage is always available for explicit save/load actions. Automatic
  save/load/apply only uses default_profile.

  Profile auto-load follows the same source-of-truth rule: live rust-analyzer
  settings win by default. A profile overrides live settings on UI open only
  with persistence.load_on_open = "always"; "if_no_client" is the safe fallback
  mode.

Persistence examples:
>
  -- Remember my last UI selection.
  -- UI opens with the saved profile even if rust-analyzer is active.
  require("cargo-features").setup({
    persistence = {
      save_on_apply = true,
      load_on_open = "always",
    },
  })

  -- Preselect saved profile only when rust-analyzer is not active.
  -- Live rust-analyzer settings win when RA is active.
  require("cargo-features").setup({
    persistence = {
      save_on_apply = true,
      load_on_open = "if_no_client",
    },
  })

  -- Manual profiles only.
  -- Use :CargoFeaturesApplyProfile <name> to apply profiles explicitly.
  require("cargo-features").setup({
    persistence = {
      save_on_apply = false,
      load_on_open = "never",
    },
  })

  -- Apply default_profile when rust-analyzer attaches.
  -- Explicit rust-analyzer Cargo/check feature settings still win.
  require("cargo-features").setup({
    persistence = {
      apply_on_attach = true,
    },
  })
<

      'ambiwidth' is "double".

LIMITATIONS                                  *cargo-features-limitations*

The current workspace behavior is most precise from a concrete package
manifest. Virtual workspace roots show package-qualified features. Default
features are controlled as a workspace-global rust-analyzer setting.

When a package manifest belongs to a larger workspace, feature names are sent
to rust-analyzer as package-qualified strings such as `my_crate/serde`.

The fallback TOML scanner is intentionally small. It extracts simple local
[features] keys only; `cargo metadata` is the source of truth whenever it is
available.

In-memory reapply matches clients by whether their root/workspace folders cover
the stored Cargo manifest path. Ambiguous multi-root layouts that cover multiple
remembered Cargo workspaces are skipped automatically and reported with a
warning. Open the command from a buffer attached to the intended rust-analyzer
client when roots are unusual.
